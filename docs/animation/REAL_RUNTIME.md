# CatalogForge real runtime evidence

This folder's runtime evidence is generated by executing the actual local
pipeline, not by drawing a storyboard with invented measurements.

## Reproduce

```powershell
py -3.12 -u scripts/generate_real_runtime_evidence.py
```

The command reads the checked-in `Synthetic_vendor_export_01.csv`, computes its
SHA-256 and intake metadata, runs the production `deterministic_extract`
function, evaluates `run_validations` for every candidate, and executes the
repository's duplicate scorer. The MP4 holds seven data-driven pipeline events
for five frames each so the trace can be inspected as a video. No candidate,
score, confidence, or source checksum is added only for visual effect.

## Model boundary

The executed path is:

- extraction: `backend/app/services/pipeline.py::deterministic_extract`
- validation: `backend/app/services/pipeline.py::run_validations`
- duplicate scoring: `backend/app/services/duplicates.py::score`
- learned model: none
- checkpoint: none
- destination: Shopify mock only

The duplicate scorer includes an `image_embedding` field, but the current code
sets it to a fixed synthetic `0.88` abstraction. No embedding model runs in
this trace, so that field is explicitly not model evidence.

The source fixture is synthetic and the parser is deterministic. Its confidence
field is a rule/parser output, not a learned-model accuracy measurement.

## Preserved outputs

- `runtime-evidence/catalogforge-runtime.mp4` — the execution trace.
- `runtime-evidence/catalogforge-runtime-poster.png` — first frame.
- `runtime-evidence/catalogforge-candidates.csv` — all extracted candidates,
  source rows, confidence, completeness, and blocking validation counts.
- `runtime-evidence/catalogforge-runtime-summary.json` — input checksum,
  candidate records, validations, duplicate score, runtime details, and output
  hashes.

The older `frontend/public/animation/catalogforge-intake-reel.html` is kept as
a legacy synthetic presentation and is not counted as model evidence.
